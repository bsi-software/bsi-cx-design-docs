Composite Content Elements

What do we mean with the term 'composite'? A composite is a content element with pre-filled dropzones. The contents of these dropzones are other, existing content elements from the design.

A practical example for a composite is a content element with two columns, where the left column contains an image content element and the right column contains a text content element.

You can build composites with classic HTML content elements or with Handlebars content elements. To keep things simple and clean, we recommend to build composites where all nested content elements have the same type: Handlebars or HTML. However, it is possible to mix the two types in a composite, but there are a few things to keep in mind when doing so. We talk about the 'mixed' case in the chapter below.

The following considerations apply for cases where the composite content element is of type Handlebars or contains a nested Handlebars content element.

Design.json

You must only define template parts for the root element.

It is also permitted for the root element to have no template parts.

The template parts for the nested content elements are defined in the corresponding content elements in the design.json. Thus, you must not redefine these template parts for the composite.

Example design.json (partial)
{
  "elementId": "two-column-composite",
  "type": "template-element",
  "file": "content-elements/two-column-composite.hbs",
  "contextFile": "content-elements/two-column-composite.json",
  "icon": "two-columns",
  "label": "Two columns with sample content",
  "templateParts": [
    {
      "partId": "plain-text",
      "partContextId": "title",
      "label": "Composite title"
    }
  ]
}

Example Template Code

Example two-column-composite.hbs
<div data-bsi-element="two-column-composite" data-bsi-context-scope="root">
  <p>{{root.text.value}}</p>
  <div data-bsi-dropzone="dzl">
    <div data-bsi-element="image" data-bsi-context-scope="dzl_image">
      <img src="{{dzl_image.image.url}}">
    </div>
  </div>
  <div data-bsi-dropzone="dzr">
    <div data-bsi-element="plain-text" data-bsi-context-scope="dzr_text">{{dzr_text.text.value}}</div>
  </div>
</div>
Every nested content element used in a composite needs to exist as a stand-alone element. The root (DOM) element of a composite content element, exists on its own. If the design had a 'two-column' content element too, which could be used stand-alone, outside the composite, this would be an independent content element with its own name. In a complex design build, you would use includes to re-use the contents from a two-columns.hbs file. So the content-element 'two-column' and 'two-column-composite' would have identical contents but different elementId properties.

A composite element needs to be built-up like building design.hbs: Every constituent element needs a data-bsi-context-scope and this scope is then used to assemble the element context.

Provide Context

You must provide a context JSON for the whole composite, including child content elements. The root element and each nested content element must have their own 'context scope'. You must always define the context scopes as top level properties in the JSON. Do not use nested JSON properties for context scopes.

Example context.json
{
  "root": {
    "text": {
      "value": "Composite title"
    }
  },
  "dzl_image": {
    "image": {
      "url": "https://example.org/picture.png"
    }
  },
  "dzr_text": {
    "text": {
      "value": "Text on the right side."
    }
  }
}

Please consider the following naming convention for context scope names:

  • The name must not contain dot (.) characters. In Handlebars this character is used for nested JSON objects.

  • Recommendation: use camel case for compound words. Example: rightText.text.value

  • Recommendation: use underscores for hierarchical paths. Example: dzr_0_rightText.text.value

Mixed Composite Content Elements

When we have a 'mixed' composite, we have a composition of content elements with mixed types: Handlebars and HTML. The following combinations are possible and supported in a composite:

  • HTML > HTML

  • Handlebars > Handlebars

  • Handlebars > HTML

  • HTML > Handlebars

If at least one content element in the chain of nested content elements is of type Handlebars, the design.json must provide a contextFile for the included Handlebars content elements, even if the root level content element is of type HTML.

Example design.json (partial)
{
  "elementId": "html-hbs-comp",
  "file": "content-elements/html/html-hbs-comp.html",
  "label": "Nested composite HTML > Handlebars",
  "contextFile": "content-elements/html/html-hbs-comp.json"
}
Example html-hbs-comp.html
<div data-bsi-element="html-hbs-comp" class="html-hbs-comp">
  <div class="row">
    <div class="col-sm-12 col-md-6 bsi-column bsi-column-1" data-bsi-dropzone="dzl">
      <div data-bsi-element="f2l8rp" data-bsi-context-scope="dzl_0" class="f2l8rp bsi-button">
        <a role="button" class="btn" href="{{ dzl_0.button.url }}">{{ dzl_0.button.text }}</a>
        <label hidden class="bsi-icon-identifier">{{ dzl_0.icon.value }}</label>
      </div>
    </div>
    <div class="col-sm-12 col-md-6 bsi-column bsi-column-2" data-bsi-dropzone="dzr">
      <div data-bsi-element="f2l8rp" data-bsi-context-scope="dzr_0" class="f2l8rp bsi-button">
        <a role="button" class="btn" href="{{ dzr_0.button.url }}">{{ dzr_0.button.text }}</a>
        <label hidden class="bsi-icon-identifier">{{ dzr_0.icon.value }}</label>
      </div>
    </div>
  </div>
</div>
Example html-hbs-comp.json (context)
{
  "dzl_0": {
    "button": {
      "url": "https://www.example.com",
      "text": "Left button",
      "openInNewWindow": false
    },
    "icon": {
      "value": "arrow-right"
    }
  },
  "dzr_0": {
    "button": {
      "url": "https://www.example.com",
      "text": "Right button",
      "openInNewWindow": false
    },
    "icon": {
      "value": "arrow-right"
    }
  }
}

How to create unique context scope names

When you work with a flexible design system for BSI CX with re-usable content elements, you should delegate the task of building technical correct, consistent and unique context scopes to a build process or -script. In the same way, the creation of context JSON files should be automated, so that context scope names in the template and in the JSON files are consistent.

The algorithm that calculates the context scope identifier should consider the hierarchy within the composite, the dropzone names and the position of the content element within a dropzone.

The following scope identifier dzr_0.button.url is from the composite example above. The scope is for the button content-element on the first position in the right dropzone of the two column root content element.
